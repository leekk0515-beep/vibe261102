# PRD: 오늘의 할일 (Today's To-Do) 웹페이지

- 문서 버전: v0.1 (설계 단계)
- 작성일: 2026-11-02
- 상태: 초안 — 구현 전

---

## 1. 개요

### 1.1 목적
사용자가 **오늘 해야 할 일**에만 집중할 수 있도록 돕는 가볍고 빠른 단일 페이지 웹 앱을 만든다. 복잡한 프로젝트 관리 도구가 아니라, 하루를 시작할 때 할 일을 적고 끝날 때까지 체크해 나가는 경험에 초점을 둔다.

### 1.2 배경 / 문제
- 기존 할일 앱은 기능이 많아 "오늘 무엇을 해야 하는가"가 흐려진다.
- 설치·회원가입 없이 브라우저에서 바로 쓸 수 있는 도구가 필요하다.

### 1.3 목표 (Goals)
1. 3초 안에 첫 할일을 추가할 수 있다.
2. 오늘의 진행률을 한눈에 볼 수 있다.
3. 새로고침하거나 브라우저를 닫았다 열어도 데이터가 유지된다.
4. 모바일·데스크톱 모두에서 편하게 사용할 수 있다.

### 1.4 비목표 (Non-Goals)
- 회원가입 / 로그인 / 서버 동기화
- 여러 사용자 간 공유·협업
- 장기 일정 관리(캘린더, 반복 일정, 알림 푸시)
- 프로젝트/태그 계층 구조

## 4. 기능 요구사항

### 4.1 헤더
- **FR-H1**: 오늘 날짜를 `2026년 11월 2일 (월)` 형식으로 표시한다.
- **FR-H2**: 진행률을 `3 / 5 완료` 텍스트와 프로그레스 바로 표시한다.
- **FR-H3**: 모든 할일이 완료되면 축하 메시지("오늘 할일을 모두 끝냈어요! 🎉")를 표시한다.

### 4.2 할일 추가
- **FR-A1**: 상단 입력창에 텍스트 입력 후 Enter 또는 [추가] 버튼으로 등록한다.
- **FR-A2**: 공백만 있는 입력은 무시한다(앞뒤 공백 trim).
- **FR-A3**: 최대 길이 100자. 초과 시 입력 불가 + 남은 글자 수 안내.
- **FR-A4**: 추가 후 입력창은 비워지고 포커스가 유지된다.
- **FR-A5 (P1)**: 우선순위 선택(기본값: 보통).

### 4.3 할일 목록
- **FR-L1**: 각 항목은 체크박스, 내용, (우선순위 배지), 삭제 버튼으로 구성된다.
- **FR-L2**: 체크 시 취소선 + 흐린 색으로 표시하고 완료 시각을 기록한다.
- **FR-L3**: 기본 정렬: 미완료 항목 먼저, 그 안에서 우선순위 → 생성 순.
- **FR-L4**: 목록이 비어 있으면 빈 상태 안내("오늘 할 일을 추가해 보세요")를 보여준다.

### 4.4 수정 / 삭제
- **FR-E1 (P1)**: 항목 내용을 더블클릭(모바일: 수정 버튼)하면 인라인 편집 모드가 된다. Enter 저장, Esc 취소, 빈 값 저장 시 기존 값 유지.
- **FR-D1**: 삭제 버튼 클릭 시 즉시 삭제하고, 5초간 [실행 취소] 토스트를 제공한다.
- **FR-D2 (P1)**: [완료 항목 지우기] 버튼으로 완료된 항목을 일괄 삭제한다.

### 4.5 필터 (P1)
- **FR-F1**: 전체 / 진행 중 / 완료 탭. 각 탭에 개수 표시.
- **FR-F2**: 마지막으로 선택한 필터를 기억한다.

### 4.6 데이터 저장
- **FR-S1**: 모든 데이터는 브라우저 `localStorage`에 저장한다.
- **FR-S2**: 변경(추가/수정/삭제/체크) 즉시 저장한다.
- **FR-S3**: 저장소 접근 실패(사생활 보호 모드 등) 시에도 앱은 동작하며, "데이터가 저장되지 않을 수 있음" 경고를 표시한다.

### 4.7 날짜 전환 (P2)
- **FR-R1**: 앱을 열었을 때 저장된 날짜가 오늘과 다르면, 미완료 항목을 오늘로 이월할지 묻는다.
- **FR-R2**: 완료 항목은 이월하지 않고 정리한다.

## 7. 데이터 모델

### 7.1 Todo 항목

```ts
interface Todo {
  id: string;            // crypto.randomUUID()
  text: string;          // 1~100자
  completed: boolean;
  priority: 'high' | 'medium' | 'low';  // 기본 'medium'
  createdAt: string;     // ISO 8601
  completedAt: string | null;
  order: number;         // 수동 정렬용 (P2)
}
```

### 7.2 저장 구조 (localStorage)

| Key | 값 | 설명 |
|---|---|---|
| `todayTodo:v1:data` | `{ date: "2026-11-02", todos: Todo[] }` | 할일 데이터 |
| `todayTodo:v1:filter` | `"all" \| "active" \| "completed"` | 마지막 필터 |
| `todayTodo:v1:theme` | `"light" \| "dark" \| "system"` | 테마 (P2) |

- 키에 버전(`v1`)을 포함해 향후 스키마 변경 시 마이그레이션 가능하게 한다.
- 파싱 실패 시 데이터를 초기화하지 않고 백업 키(`...:backup`)에 원본을 보존한다.

## 8. 기술 설계

### 8.1 기술 스택 (제안)
- **HTML + CSS + Vanilla JavaScript (ES Modules)** — 빌드 도구 없이 정적 파일로 동작
- 선택 이유: 기능 규모가 작고, 의존성 없이 바로 배포·실행 가능
- 대안: 기능이 커지면 Vite + React/TypeScript로 전환 고려

### 8.2 폴더 구조 (예정)

```
todolist/
├── prd.md            # 본 문서
├── index.html        # 마크업
├── css/
│   └── style.css     # 테마 변수, 레이아웃, 컴포넌트 스타일
└── js/
    ├── main.js       # 앱 초기화, 이벤트 바인딩
    ├── store.js      # 상태 관리 + localStorage 읽기/쓰기
    ├── render.js     # 목록/헤더/필터 렌더링
    └── utils.js      # 날짜 포맷, id 생성 등
```

### 8.3 아키텍처
- **단방향 데이터 흐름**: 사용자 이벤트 → `store`의 액션(add/toggle/edit/remove/clearCompleted/setFilter) → 상태 갱신 & 저장 → `render(state)` 호출
- 상태는 `store.js`의 단일 객체에서만 변경한다.
- 렌더링은 상태 전체를 기준으로 다시 그리되, 항목 수가 적으므로 단순 재렌더링으로 충분하다.
- 사용자 입력 텍스트는 `textContent`로만 삽입해 XSS를 방지한다(`innerHTML` 사용 금지).

### 8.4 주요 액션 정의

| 액션 | 입력 | 동작 |
|---|---|---|
| `addTodo` | text, priority | 검증 후 목록에 추가 |
| `toggleTodo` | id | completed 반전, completedAt 갱신 |
| `editTodo` | id, text | 검증 후 text 변경 |
| `removeTodo` | id | 삭제 + 실행 취소용 임시 보관 |
| `undoRemove` | — | 마지막 삭제 항목 복원 |
| `clearCompleted` | — | 완료 항목 일괄 삭제 |
| `setFilter` | filter | 필터 변경 및 저장 |

## 11. 수용 기준 (MVP)
